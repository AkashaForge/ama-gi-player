## 0. Document control

This document is the privacy policy (Data Protection Notice) of
the Amagi-Player software and is published in the project
repository. The current version is available at:
`https://github.com/AkashaForge/ama-gi-player/blob/main/PRIVACY.md`.

The document follows the layered-notice model recommended by
Art. 12(7) GDPR and equivalent data-protection regimes: a short
summary, an overview table, the full text, and technical annexes.
All layers form a single document and do not contradict each
other.

---

## 1. Definitions

**1.1. "Application"** — the Amagi-Player software distributed
under the GNU GPL v3.0 license, including source code, executables,
configuration files, and documentation.

**1.2. "Developer"** — the natural or legal person developing and
publishing the Application (AkashaForge). The Developer is not a
controller of the User's personal data within the meaning of
applicable law.

**1.3. "User"** — a natural person using the Application on their
own device.

**1.4. "Device"** — the hardware of the User on which the
Application is installed and operates.

**1.5. "Source"** — an external network service or local program
that the Application contacts to obtain content or metadata
(Internet Archive, user-defined sources, locally running external
indexers).

**1.6. "Personal data"** — information relating to an identified
or identifiable natural person, within the meaning of Art. 4(1)
GDPR and equivalent norms.

**1.7. "Processing"** — any operation on personal data, including
collection, recording, storage, modification, retrieval, use,
transfer, and erasure.

**1.8. "Local data"** — data created and stored by the Application
exclusively on the User's Device.

---

## 2. Scope

**2.1. Within the scope of this Policy:**

- processing of data by the Application on the User's Device;
- network requests initiated by the Application;
- local logs generated by the Application;
- configuration files created or modified by the User.

**2.2. Outside the scope of this Policy:**

- processing of data by the Device's operating system;
- processing of data by Sources (governed by the respective
  Source's policies);
- processing of data by third-party programs installed by the
  User themselves;
- processing of data on GitHub's side in connection with the
  project repository.

---

## 3. Roles and responsibilities

**3.1.** The Developer **does not act** as a controller or
processor of the User's personal data within the meaning of
Art. 4(7)–(8) GDPR, because:

- the Developer does not receive the User's personal data;
- the Developer has no technical means of accessing the User's
  Device;
- the Developer does not process personal data on behalf of, or
  under the instruction of, the User.

**3.2.** The User is the sole party controlling the processing of
Local data on their Device.

**3.3.** The User's interaction with Sources is governed by the
policies of the respective Sources. The Developer is not a party
to those relationships.

---

## 4. Lawful basis and principles

**4.1.** The processing of Local data is carried out by the
Application solely for the purpose of its own operation and on
the basis of the User's consent given on first launch
(Art. 6(1)(a) GDPR), as well as for the performance of the
agreement on use of the Application (Art. 6(1)(b) GDPR).

**4.2.** The Application adheres to the principles of:

- **minimization** (Art. 5(1)(c) GDPR) — only the strict minimum
  of data is processed;
- **storage limitation** (Art. 5(1)(e) GDPR) — data is stored
  until the User deletes it;
- **transparency** (Art. 5(1)(a) GDPR) — this Policy describes
  every category of data;
- **integrity and confidentiality** (Art. 5(1)(f) GDPR) — data
  does not leave the User's Device;
- **accountability** (Art. 5(2) GDPR) — this document records the
  architectural decisions that preclude processing of personal
  data by the Developer.

**4.3.** Because the Developer does not process the User's
personal data, the obligations under Art. 30 GDPR (records of
processing activities) do not apply to the Developer.

## 5. Data inventory — categories of processed data

**5.1.** The Application processes the following categories of
Local data:

| # | Category | Format | Location | Purpose | Retention |
|---|---|---|---|---|---|
| 1 | Watch history | SQLite | application folder | "Continue watching" | until deleted by User |

provided in Annex A (Technical data inventory).

**5.3.** None of the listed categories is transmitted to the
Developer or to third parties on the Developer's behalf.

## 7. Network interactions

**7.1.** The Application initiates network requests solely to
obtain content and metadata from Sources.

**7.2.** Typical network interactions:

| # | Recipient | Trigger | Data transmitted |
|---|---|---|---|
| 1 | Internet Archive (`archive.org`) | search, playback | IP address, User-Agent, HTTP headers, search query |
| 2 | User-defined sources (`sources.txt`) | if added by the User | IP address, User-Agent, HTTP headers, search query |
| 3 | Local external indexer (e.g., Jackett at `localhost`) | if installed by the User | HTTP request over loopback |

**7.3.** Transmission of the IP address, User-Agent, and HTTP
headers is an inherent property of the HTTP protocol and is not
the result of any data collection by the Developer.

**7.4.** The Developer does not control data processing by
Sources and is not responsible for such processing. Each Source's
privacy policy is determined by that Source.

**7.5.** Users for whom additional privacy during network
interactions matters may apply standard operating-system or
network-layer tools at their own discretion. The Application
neither requires nor configures such tools automatically.

**7.6.** A full specification of network endpoints is provided
in Annex B (Network endpoints).

---

## 8. Third parties and sub-processors

**8.1.** The Developer does not engage processors or
sub-processors to process the User's personal data.

**8.2.** The Developer does not transfer Local data to third
parties.

**8.3.** The Developer does not perform any international
transfer of the User's personal data, because it does not receive
such data.

---

## 9. Retention

**9.1.** The retention period for Local data is unlimited and is
determined solely by the User.

**9.2.** Local data is erased:

- through the Application settings (cleanup function);
- manually — by deleting the corresponding files and folders;
- when the Application is removed from the Device.

**9.3.** Once deleted, Local data cannot be restored by the
Application's own means.

---

## 10. Security measures

**10.1.** The Application applies the following protections for
Local data:

- no network transmission of Local data to the Developer's
  servers;
- no remote access to the User's Device by the Developer;
- isolation of child processes (ffmpeg, headless browser) with
  lifetime control;
- no built-in remote-control mechanisms.

**10.2.** Protection of the Device at the operating-system level
(disk encryption, user privilege separation, antivirus
protection) is the User's responsibility.

**10.3.** Because the Developer does not process the User's
personal data, the obligations under Art. 32 GDPR (security of
processing) do not apply to the Developer. The measures listed
in §10.1 are applied voluntarily in the User's interest.

the manner prescribed by the law of their jurisdiction.

## 12. Children

**12.1.** The Application is not intended for use by persons
below the age at which, under their jurisdiction's law, they
can independently consent to the processing of personal data
(Art. 8 GDPR; COPPA in the US — 13 years).

**12.2.** The Developer does not knowingly collect or process
data of persons below that age.

**12.3.** If the User is a parent or guardian and believes that
a minor is using the Application without proper consent, they
may uninstall the Application from the Device.

## Annex A — Technical data inventory

Specification of Local data at the file-system and format level.

### A.1. Watch history

| Field | Value |
|---|---|

## Annex C — Logging specification

**C.1.** The Application keeps local logs solely for error
diagnostics.

**C.2.** The following are **not** written to the logs:

- IP addresses of Sources;
- the User's search queries;
- HTTP header contents;
- the User's personal data.

**C.3.** The following **are** written to the logs:

- timestamps;
- logging levels;
- module identifiers;
- error messages and stack traces.

**C.4.** Logs are not transmitted to the Developer and are not
sent to any network endpoint.

**C.5.** The User may delete the logs at any time by removing
the `logs/` folder.
