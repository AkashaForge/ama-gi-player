## 0. Контроль документа

Настоящий документ является политикой конфиденциальности (Уведомлением о
защите данных) программного обеспечения Amagi-Player и публикуется в
репозитории проекта. Актуальная версия доступна по адресу
`https://github.com/AkashaForge/ama-gi-player/blob/main/PRIVACY.md`.

Документ следует модели многоуровневого уведомления, рекомендованной
ст. 12(7) GDPR и аналогичными режимами защиты данных: краткое резюме,
обзорная таблица, полный текст и технические приложения. Все уровни
образуют единый документ и не противоречат друг другу.

Документ составлен с учётом:

- **Европейский союз**: General Data Protection Regulation (GDPR), 2016/679;
- **Соединённые Штаты Америки**: COPPA (15 U.S.C. §§ 6501–6506);
  California Consumer Privacy Act с поправками CPRA (Cal. Civ. Code
  § 1798.100 et seq.); Virginia Consumer Data Protection Act
  (Va. Code § 59.1 et seq.); Colorado Privacy Act (C.R.S. § 6-1-1301
  et seq.); Connecticut Data Privacy Act (Conn. Gen. Stat. § 42-515 et seq.);
- **Российская Федерация**: Федеральный закон от 27.07.2006 № 152-ФЗ
  «О персональных данных» (в действующей редакции).

Поскольку Приложение не обрабатывает персональные данные на инфраструктуре
Разработчика (см. §3), ни один из перечисленных режимов не создаёт
обязанностей для Разработчика. Ссылки приведены для прозрачности и для
описания того, как права Пользователя реализуются локально.

## 1. Определения

**1.1. «Приложение»** — программное обеспечение Amagi-Player, распространяемое
под лицензией GNU GPL v3.0, включая исходный код, исполняемые файлы,
конфигурационные файлы и документацию.

**1.2. «Разработчик»** — физическое или юридическое лицо, разрабатывающее и
публикующее Приложение (AkashaForge). Разработчик не является контролёром
или оператором персональных данных Пользователя в смысле применимого
законодательства.

**1.3. «Пользователь»** — физическое лицо, использующее Приложение на своём
устройстве.

**1.4. «Устройство»** — аппаратное обеспечение Пользователя, на котором
установлено и работает Приложение.

**1.5. «Источник»** — внешний сетевой сервис, к которому Приложение
обращается для получения контента или метаданных (Internet Archive, API
Кинопоиска, пользовательские источники, локальные внешние индексаторы).

**1.6. «Персональные данные»** — информация, относящаяся к
идентифицированному или идентифицируемому физическому лицу, в смысле
ст. 4(1) GDPR, ст. 3 152-ФЗ и аналогичных норм.

**1.7. «Обработка»** — любая операция с персональными данными, включая сбор,
запись, хранение, изменение, извлечение, использование, передачу и
уничтожение.

**1.8. «Локальные данные»** — данные, создаваемые и хранимые Приложением
исключительно на Устройстве Пользователя, под полным контролем
Пользователя.

## 2. Область действия

**2.1. В область действия настоящей Политики входит:**

- обработка Локальных данных Приложением на Устройстве Пользователя;
- сетевые запросы, инициируемые Приложением;
- конфигурационные файлы, создаваемые или изменяемые Пользователем
  (`data/mode.txt`, `data/sources.txt`, `.env`);
- диагностический вывод Приложения в консоль.

**2.2. Вне области действия настоящей Политики:**

- обработка данных операционной системой Устройства;
- обработка данных Источниками (регулируется политиками соответствующих
  Источников);
- обработка данных сторонними программами, установленными Пользователем;
- обработка данных на стороне GitHub в связи с репозиторием проекта.

## 3. Роли и ответственность

**3.1.** Разработчик **не выступает** контролёром, обработчиком или
оператором персональных данных Пользователя, поскольку:

- Разработчик не получает персональные данные Пользователя;
- Разработчик не имеет технических средств доступа к Устройству
  Пользователя;
- Разработчик не обрабатывает персональные данные от имени Пользователя
  или по его поручению.

**3.2.** Пользователь является единственной стороной, контролирующей
обработку Локальных данных на своём Устройстве. Согласно 152-ФЗ Пользователь
является оператором любых персональных данных, содержащихся в `.env`
(при наличии API-ключа).

**3.3.** Взаимодействие Пользователя с Источниками регулируется политиками
соответствующих Источников. Разработчик не является стороной этих
отношений.

## 4. Правовые основания и принципы

**4.1.** Обработка Локальных данных осуществляется Приложением исключительно
для его собственного функционирования, на основании согласия Пользователя,
данного при первом запуске (ст. 6(1)(a) GDPR; ст. 9 152-ФЗ), и для
исполнения соглашения об использовании Приложения (ст. 6(1)(b) GDPR).

**4.2.** Приложение придерживается принципов:

- **минимизации** (ст. 5(1)(c) GDPR; ст. 5 152-ФЗ) — обрабатывается строго
  минимальный объём данных;
- **ограничения хранения** (ст. 5(1)(e) GDPR) — данные хранятся до их
  удаления Пользователем;
- **прозрачности** (ст. 5(1)(a) GDPR; ст. 18 152-ФЗ) — настоящая Политика
  описывает каждую категорию данных;
- **целостности и конфиденциальности** (ст. 5(1)(f) GDPR) — данные не
  покидают Устройство Пользователя (за единственным исключением сетевых
  запросов, см. §7);
- **подотчётности** (ст. 5(2) GDPR) — настоящий документ фиксирует
  архитектурные решения, исключающие обработку персональных данных
  Разработчиком.

**4.3.** Поскольку Разработчик не обрабатывает персональные данные,
обязанности по ст. 30 GDPR (реестр операций обработки) и ст. 22 152-ФЗ
(уведомление Роскомнадзора) к Разработчику не применяются.

## 5. Категории обрабатываемых данных

**5.1.** Приложение обрабатывает следующие категории Локальных данных.

| № | Категория | Формат | Расположение | Назначение | Хранение |
|---|---|---|---|---|---|
| 1 | История просмотров | SQLite | `data/app_data.db` (таблица `user_history`) | «Продолжить просмотр» | до удаления Пользователем |
| 2 | Кэш постеров | JPEG/PNG | `data/cache/{kp_id}.jpg` | производительность UI | до удаления Пользователем |
| 3 | Кэш метаданных | JSON | `data/cache/short/{id}.json`, `data/cache/full/{id}.json`, `data/cache/lists/{hash}.json` | сокращение сетевых запросов | до удаления Пользователем |
| 4 | Каталог фильмов | SQLite | `data/whitelist.db` (на основе поставляемого `data/whitelist_seed.db`) | лента фильмов общественного достояния | в составе Приложения; пересоздаётся из seed |
| 5 | Выбор режима | plain text | `data/mode.txt` | режим (`public` / `private`) | до удаления Пользователем |
| 6 | Список источников | plain text | `data/sources.txt` | пользовательские источники | до удаления файла |
| 7 | API-ключи | plain text | `.env` (рядом с exe) | опциональный доступ к API Кинопоиска | до удаления Пользователем |
| 8 | Диагностика | plain text (консоль) | stderr (не сохраняется) | диагностика | не хранится |

**5.2.** Ни одна из перечисленных в §5.1 категорий не передаётся Разработчику
или третьим лицам от имени Разработчика.

**5.3.** `config.py` — **read-only модуль исходного кода** с параметрами по
умолчанию (пути, таймауты, feature-флаги). Он **не является хранилищем
данных** и не содержит пользовательских данных. Пользовательские настройки
хранятся только в `.env` и в `data/*.txt`, перечисленных выше.

**5.4.** Полные технические спецификации — в Приложении A.

## 6. Категории, которые НЕ обрабатываются

**6.1.** Приложение не обрабатывает следующие категории:

| № | Категория | Обрабатывается |
|---|---|---|
| 1 | Имя, фамилия, email, телефон, почтовый адрес | **нет** |
| 2 | Учётные данные (логины, пароли, токены доступа) | **частично** — см. §6.2 |
| 3 | Платёжная информация | нет |
| 4 | Биометрические данные | нет |
| 5 | Геолокация (GPS, IP-геолокация) | нет |
| 6 | Контакты, файлы, сообщения с Устройства | нет |
| 7 | Аналитика использования | нет |
| 8 | Телеметрия, отчёты о сбоях | нет |
| 9 | Рекламные идентификаторы | нет |
| 10 | Данные фингерпринтинга (canvas, шрифты, WebGL) | нет |

**6.2. API-ключ (исключение из №2).** Опциональный API-ключ Кинопоиска
может храниться в `.env` по усмотрению Пользователя. Это не учётные данные
какого-либо аккаунта, принадлежащего Разработчику; он идентифицирует
Пользователя только перед API Кинопоиска (`kinopoiskapiunofficial.tech`) и
передаётся только этому сервису и только когда Пользователь инициирует
запрос метаданных. В режиме `public` API Кинопоиска **не вызывается**.
Разработчик **никогда** не получает этот ключ.

**6.3.** Приложение не содержит модулей аналитики, рекламы, телеметрии,
crash-reporting или A/B-тестирования.

## 7. Сетевые взаимодействия

**7.1.** Приложение инициирует сетевые запросы исключительно для получения
контента и метаданных из Источников, выбранных Пользователем.

**7.2.** Типичные сетевые взаимодействия:

| № | Получатель | Триггер | Передаваемые данные |
|---|---|---|---|
| 1 | Internet Archive (`archive.org`) | поиск, воспроизведение | IP-адрес, User-Agent, HTTP-заголовки, поисковый запрос |
| 2 | API Кинопоиска (`kinopoiskapiunofficial.tech`) | опционально, только если задан `KP_API_KEY` **и** режим `private` | IP-адрес, User-Agent, API-ключ, идентификатор фильма |
| 3 | Пользовательские источники (`data/sources.txt`) | если добавлены Пользователем | IP-адрес, User-Agent, HTTP-заголовки, поисковый запрос |
| 4 | Локальный внешний индексатор (например, Jackett на `localhost`) | если установлен Пользователем | HTTP-запрос через loopback |
| 5 | BitTorrent-свармы Internet Archive | воспроизведение только в режиме `private` | IP-адрес, порт, BitTorrent peer-id |

**7.3.** Передача IP-адреса, User-Agent и HTTP-заголовков — неотъемлемое
свойство протокола HTTP и не является результатом сбора данных
Разработчиком.

**7.4.** Разработчик не контролирует обработку данных Источниками и не
несёт за неё ответственности. Политика конфиденциальности каждого
Источника определяется этим Источником.

**7.5.** Пользователи, для которых важна дополнительная приватность при
сетевых взаимодействиях, могут по своему усмотрению применять стандартные
средства операционной системы или сетевого уровня. Приложение не требует и
не настраивает такие средства автоматически.

**7.6.** Полная спецификация эндпоинтов — в Приложении B.

## 9. Хранение

**9.1.** Срок хранения Локальных данных не ограничен и определяется
исключительно Пользователем.

**9.2.** Локальные данные удаляются:

- через настройки Приложения (функция очистки);
- вручную — путём удаления соответствующих файлов и папок;
- при удалении Приложения с Устройства.

**9.3.** После удаления Локальные данные не могут быть восстановлены
средствами самого Приложения.

## 10. Меры безопасности

**10.1.** Приложение применяет следующие меры защиты Локальных данных:

- отсутствие сетевой передачи Локальных данных на серверы Разработчика;
- отсутствие удалённого доступа к Устройству со стороны Разработчика;
- изоляция дочерних процессов (FFmpeg, headless-браузер) с контролем
  времени жизни;
- отсутствие встроенных механизмов удалённого управления.

**10.2.** Защита Устройства на уровне операционной системы (шифрование
диска, разделение привилегий, антивирусная защита) — ответственность
Пользователя.

**10.3.** Поскольку Разработчик не обрабатывает персональные данные,
обязанности по ст. 32 GDPR (безопасность обработки) и ст. 19 152-ФЗ (меры
по обеспечению безопасности) к Разработчику не применяются. Меры,
перечисленные в §10.1, применяются добровольно в интересах Пользователя.

## Приложение A — Техническая инвентаризация данных

### A.1. История просмотров

| Поле | Значение |
|---|---|
| Файл | `data/app_data.db` |
| Формат | SQLite 3 (WAL) |
| Таблица | `user_history` |
| Поля | `kp_id INTEGER`, `movie_title TEXT`, `current_seconds REAL`, `duration_sec REAL`, `updated_at TIMESTAMP` |
| Передача вовне | отсутствует |

### A.2. Кэш постеров

| Поле | Значение |
|---|---|
| Папка | `data/cache/` |
| Формат | JPEG, PNG |
| Имена | `{kp_id}.jpg` |
| Передача вовне | отсутствует |

### A.3. Кэш метаданных

| Поле | Значение |
|---|---|
| Папки | `data/cache/short/`, `data/cache/full/`, `data/cache/lists/` |
| Формат | JSON (один файл на запись) |
| Имена | `{id}.json` (short/full), `{hash}.json` (lists) |
| Заполняется | только при использовании API Кинопоиска (режим `private`) |

### A.4. Каталог фильмов

| Поле | Значение |
|---|---|
| Файл | `data/whitelist.db` (рабочая), `data/whitelist_seed.db` (поставляемая) |
| Формат | SQLite 3 |

| Содержит данные пользователя | нет (метаданные public-domain фильмов из Internet Archive) |
| Передача вовне | отсутствует |

### A.5. Выбор режима

| Поле | Значение |
|---|---|
| Файл | `data/mode.txt` |
| Формат | plain text (`public` или `private`) |

## Приложение C — Спецификация журналирования

**C.1.** Приложение пишет диагностику **только в консоль (stderr)**.
Файловые журналы по умолчанию не создаются.

**C.2.** В диагностику **не** записываются:

- IP-адреса Источников;
- поисковые запросы Пользователя;
- содержимое HTTP-заголовков;
- персональные данные Пользователя (включая API-ключи).

**C.3.** В диагностику **записываются**:

- метки времени;
- уровни логирования;
- идентификаторы модулей;
- сообщения об ошибках и стектрейсы.

**C.4.** Диагностика не передаётся Разработчику и не отправляется на
сетевые эндпоинты.

**C.5.** Если Пользователь включит файловое логирование, местоположение и
срок хранения определяются конфигурацией Пользователя; Разработчик эти
логи не получает.
