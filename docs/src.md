# Amagi-Player — Software Requirements Specification

**Версия:** 1.0
**Дата:** 2025-11-06
**Автор:** AkashaForge

---

## 1. Введение

### 1.1. Назначение

Десктопное приложение для поиска и стриминга фильмов общественного
достояния из Internet Archive. Два режима работы: **PUBLIC** (только IA,
легальный контент) и **PRIVATE** (P2P через libtorrent, для разработчиков).

### 1.2. Область применения

Локальное приложение для конечных пользователей. Не клиент-серверное,
без аккаунтов, без телеметрии. Сетевые запросы — только к тем источникам,
которые пользователь явно использует для поиска и воспроизведения.

### 1.3. Проблема

Пользователь хочет посмотреть классический фильм из открытого архива,
но:
- Internet Archive неаккуратен: метаданные врут, один фильм залит
  несколько раз, файлы бывают DVD-образами (mpeg), которые ломаются при seek
- Скачать целиком — долго и не всегда нужно
- Существующие плееры либо для коммерческого контента, либо не работают
  с открытыми архивами

### 1.4. Определения

| Термин | Определение |
|---|---|
| **PD** | Public domain — общественное достояние |
| **IA** | Internet Archive |
| **P2P** | Peer-to-peer, BitTorrent |
| **HTTP Range** | Частичный HTTP-запрос (`Range: bytes=X-Y`) |
| **Piece** | Фрагмент торрента (обычно 256 KB – 4 MB) |
| **Magnet** | Ссылка на торрент по info_hash без `.torrent` файла |
| **Swarm** | Группа пиров, обменивающихся одним торрентом |
| **Composite health score** | Взвешенная оценка источника |
| **PYNORM** | SQLite-функция для Unicode-lowercase + ё→е |

## 2. Функциональные требования

### 2.1. Лента и поиск

| ID | Требование | Критерий приёмки |
|---|---|---|
| **F-01** | Система отображает ленту из локального каталога по 20 карточек на страницу. При первом запуске в PUBLIC-режиме — 20 карточек с постерами. | Открыть приложение → 20 карточек, у каждой постер. |
| **F-02** | Поиск по названию (RU/EN) и году. Регистронезависимый для кириллицы. | Запрос «МАТРИЦА» находит «Матрица». Запрос «1922» находит все фильмы 1922 года. |
| **F-03** | При скролле к низу — подгрузка следующей страницы. После последней страницы — новых нет. | Скролл до конца → новые карточки; после N страниц — «больше нет». |
| **F-04** | Постерный каскад: локальный кэш → постеры из релиза → IA thumbnail → KP (опционально). Файлы < 2 KB считаются «недоступна». | Постер ≤ 3 секунд после карточки. |
| **F-05** | Если постера нет ни на одном шаге — placeholder «ОБЛОЖКА НЕДОСТУПНА», не пустое место. | Карточка без постера показывает placeholder. |

### 2.2. Стриминг PUBLIC (Internet Archive)

| ID | Требование | Критерий приёмки |
|---|---|---|
| **F-06** | Поиск в IA — каскад из 4 запросов от строгого к широкому. Каждый следующий запускается **только** если предыдущий вернул 0 результатов. | В логах `IA query:` для каждого шага. Если первый дал 50 — остальные 3 не запускаются. |
| **F-07** | Допуск по году ±2: для 1921 → `[1919, 1923]`. Метаданные IA часто ошибаются на год-два. | Для «The Kid» (1921) — `year:[1919 TO 1923]`. |
| **F-08** | Скоринг кандидатов: language × 100 + title accuracy × 50 + popularity × 20. Sort desc, top 15. | В логах `IA итог: N direct_url`, отсортировано по score. |
| **F-09** | Для фильмов до 1930 год язык — **не** дисквалификатор. Возвращает 0.9 (не 1.0, но и не 0.0). Старые фильмы часто помечены языком субтитров, а не оригинальным. | «Nosferatu» (1922) проходит языковой фильтр независимо от языка в метаданных. |
| **F-10** | Выбор файла в элементе — приоритет расширения. MP4 > WebM > MKV > M4V > OGV > MOV > AVI > WMV > MPG > MPEG. При равном приоритете — больший размер. | Если в элементе mp4 2 GB и mpeg 5 GB — выбран mp4 (приоритет 100 против 3). |
| **F-11** | Файлы вне диапазона [30 MB, 4 GB] игнорируются. Трейлеры (по имени или размеру < 50 MB) игнорируются. | В логах `metadata {id}: no playable video in N files` если ничего не подошло. |
| **F-12** | Если в элементе только «неудобные» форматы (mpeg, mpg, wmv) — плеер всё равно берёт лучший из них, но логирует предупреждение. | В логах `only unfriendly format {ext} available`. |
| **F-13** | При demux error от QMediaPlayer — 1 retry через 5 секунд к тому же URL. Если retry не помог — переход к следующему direct_url. | В логах `public DEMUX → retry in 5s (attempt 1/1)`, потом `direct: переключение на N/M`. |
| **F-14** | Если retry не помог и других direct_url нет — сообщение «Все варианты испробованы», возврат в ленту. | После 2-й неудачи — нет крэша, есть сообщение. |

### 2.3. Стриминг P2P (libtorrent)

| ID | Требование | Критерий приёмки |
|---|---|---|
| **F-15** | До 12 кандидатов одновременно. Группировка по info_hash, объединение трекеров в группах (один торрент часто приходит из 3–5 источников). | В логах `Taking N candidates`, `Merged swarm {hash} xN`. |
| **F-16** | Выбор победителя: score = rate × log10(peers) × has_first × piece_size_mult. Grace period 10 секунд — не выбираем мгновенно, даём шанс медленным торрентам. Margin 2.0 — переключение только если новый в 2 раза лучше. | В логах `First ready: N peers, X MB/s, has_first=Y, score=Z`. |
| **F-17** | Мёртвые handles убиваются: no peers 10s, no metadata 60s, no first piece 45s. Не ждём до таймаута 30s — освобождаем слоты для живых. | В логах `Kill {key}: reason`. |
| **F-18** | HTTP Range сервер слушает `127.0.0.1` (auto port). Проверка Host-header: пустой или чужой → 403. | `curl http://127.0.0.1:PORT/stream` работает; `curl -H "Host: evil.com"` → 403. |
| **F-19** | Piece scheduler использует `set_piece_deadline(piece, ms)` с положительным deadline (минимум 100ms). `set_piece_deadline(piece, 0)` = «no deadline», libtorrent его игнорирует. Lookahead 10 pieces, step 150ms, tail 20 pieces с deadline 1000ms. | Seek работает ≤ 5 секунд. |
| **F-20** | `force_deadline` вызывается при **каждом** HTTP Range запросе (не только через `on_position`). FFmpeg probe в середине файла не попадает в playhead, но deadline должен быть поставлен. | В логах `force_deadline: piece=N la=M` при каждом seek. |
| **F-21** | `cancel()` освобождает handles: async remove + polling до 15s + sync fallback. **Alert pump остаётся живым** во время polling (обрабатывает removals), останавливается **после**. | В логах `Session state before add: 0 torrents` при следующем старте. |
| **F-22** | Если 15s polling не помог — sync `remove_torrent` для оставшихся handles. Один вызов, быстрый. Не блокировать UI. | В логах `cancel: async_remove_torrent не удалил за 15.0s — sync remove для N handles`. |
| **F-23** | `rmtree` downloads_dir выполняется в executor (не блокирует main thread). Для 25GB торрента — секунды, но UI не замирает. | Seek работает во время cleanup. |

### 2.4. Fallback (многоуровневый)

| ID | Требование | Критерий приёмки |
|---|---|---|
| **F-24** | 4 уровня fallback: online (m3u8/mp4) → public direct (IA) → P2P (libtorrent) → private direct. Каждый уровень изолирован. | При падении online — переход на direct; при падении direct — на P2P; и т.д. |
| **F-25** | PUBLIC: `_public_epoch` защищает от race — QTimer старого стрима не выстрелит в новый. | После закрытия стрима во время retry: `public retry: stream reset (epoch X != Y), skip`. |
| **F-26** | PUBLIC: skip на последнем direct_url → начинаем с первого (циклический перебор). | В логах `Skip: последний источник, начинаем с первого`. |
| **F-27** | PRIVATE: demux error → reload #1 через 5s → auto-fallback до 3 попыток. Альтернативы через `SourceSelector.rank()` (не `_score()` — этого метода нет). | В логах `auto-fallback [N/3]: 'title' (score)`. |
| **F-28** | Watchdog буферизации: buffering > 25s и rate < 0.3 MB/s → принудительный stop + fallback. Buffering > 30s → stop (без fallback сразу). | В логах `WATCHDOG: Xs, rate=Y, peers=Z → fallback`, `Buffer 30s — stop`. |
| **F-29** | `player.stop()` в buffer_monitor вызывается через `QTimer.singleShot(0, ...)` — не sync в QTimer callback. | UI не замирает при watchdog. |

## 3. Нефункциональные требования

### 3.1. Производительность

| ID | Требование | Критерий приёмки |
|---|---|---|
| **N-01** | Время до первого кадра P2P ≤ 30 секунд. По истечении — FAILED с понятным сообщением. | Timeout без готового источника → «Ни один из N не начал качать». |
| **N-02** | `wait_for_piece` polling 50ms, refresh deadline каждые 5s. | В логах `wait_piece N: X.Xs` не чаще раза в 3 секунды. |
| **N-03** | `read_piece` timeout 8s. | По истечении — `read_piece N alert timeout`, fallback на файл. |
| **N-04** | Время запуска приложения (до главного окна) ≤ 3 секунд на SSD. | Замер от `main.py` до `main_window.show()`. |
| **N-05** | Время загрузки первой страницы ленты (20 карточек) ≤ 2 секунд на SSD. | Замер от `load_feed()` до `end_batch()`. |
| **N-06** | Время отклика UI на клик ≤ 100 мс. | Клик на карточку → переход на детали. |

### 3.2. Надёжность

| ID | Требование | Критерий приёмки |
|---|---|---|
| **N-07** | `handle_close_player` — 2 фазы: `stop_and_save()` → 200ms → `_start_close_async()`. Без паузы libtorrent не может удалить torrent (QMediaPlayer держит file handle). | В логах `Закрытие плеера` → (200ms) → `Плеер закрыт`. |
| **N-08** | Watchdog на `_closing_in_progress` — 30s. Если залип — сбрасывается насильно. | В логах `WATCHDOG: _closing_in_progress залип >30000ms`. |
| **N-09** | `_stop_resources()` идемпотентен: ссылка отвязывается **до** `await cancel()`. Второй вызов видит `None`, не падает. | Двойной вызов (close + cascade) не ломает. |
| **N-10** | `asyncio.wait_for(_stop_resources(), timeout=25.0)`. Timeout → сессия «утекла», но UI разблокирован. | Timeout → `close_player: _stop_resources timeout 25s`, не крэш. |
| **N-11** | При повторном запуске после падения — нет зомби (Jackett, Prowlarr, Chrome). | `cleanup_startup()` в `orchestrator.__init__`. В логах `Убит зомби-Jackett pid=N`. |

| ID | Требование | Критерий приёмки |

## 4. Что НЕ входит (Out of Scope)

Явно **не** реализуется в v1.0 — осознанное решение, не «не успел»:

- **macOS** — не тестировалось, нет машины для поддержки
- **Мобильные платформы** — десктопное приложение
- **Субтитры** — Qt покажет встроенные в MKV, но UI выбора нет
- **Выбор аудиодорожки** — UI нет
- **Chromecast / AirPlay / DLNA** — SDK, дни работы, для 130 фильмов overkill
- **Пользовательские аккаунты** — приложение локальное
- **Облачная синхронизация** — противоречит «no telemetry»
- **ML-рекомендации** — не та задача, не тот масштаб
- **Скачивание для офлайн** — стриминг закрывает потребность
- **Code signing** — в roadmap, но стоит денег
- **Английский UI** — EN/RU переключает поиск, не интерфейс
- **Взрослый контент / 18+** — каталог фильтрован (PD)
- **Пользовательские плейлисты** — не в v1.0
- **Поиск по режиссёру / актёру** — в БД только title/year

## 5. Известные компромиссы

Места, где можно лучше, но осознанно не сделано в v1.0:

| Что | Почему оставил | Цена |
|---|---|---|
| `_sync_card_filters` через QTimer 300ms | Проще, чем сигнал из `add_card_to_grid` | Оверхед 3 r/sec на поиск по виджетам |
| `paintEvent` шум попиксельно | Только light theme + header bar | O(w·75) на resize |
| `_read_json`/`_write_json` sync в `kp_service` | JSON 5–10 KB, миллисекунды | Блокировка loop ~40ms в PRIVATE |
| N+1 в `_build_movies_from_whitelist` | 20 карточек — незаметно | 21 запрос вместо 1 |
| Нет тестов на fallback | Моки libtorrent — отдельная задача | Непокрытая сложная логика |
| `print()` в `config.py` | `import config` до `setup_logging` | Логи до инициализации — в stdout |

Эти компромиссы **известны**, не «забыл». На защите можно объяснить каждый.

## 7. Критерии готовности проекта

Проект считается выполненным, если:

1. **Все функциональные требования** (F-01…F-42) выполнены и проверены
2. **Все нефункциональные требования** (N-01…N-20) выполнены или обоснованно отклонены
3. **Сборка Nuitka** проходит, `.dist` содержит `amagi-player.exe` + `data/` + `ui/`
4. **Smoke-тесты** (`pytest`) проходят
5. **Документация** (README EN/RU, LICENSE, LICENSES, NOTICE, README-LINUX) в наличии
6. **Демонстрация** на защите: public + private + переключение режимов
